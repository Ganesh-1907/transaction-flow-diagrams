Built URL

Pay link Built by BX when the sale is created, sent in the request email:
<program registration_url>/additional-sale?ref=<registration_id>+<T id>

The + is a space. rx splits ref into the registration id and the T id (separate trxn_id or trxnId parameters also work).

Thank you link After the gateway, success or processing goes to:
<rx origin>/<locale>/programs/<program_id>/thankyou?ref=<registration_id>&caps_transaction_id=<CAPS id>

Fail link Failed, or any other status, goes to:
<rx origin>/<locale>/programs/<program_id>/failed?ref=<registration_id>%20<T id>&caps_transaction_id=<CAPS id>

The Try again button on the failed page opens the retry-payment page with the same ref (registration id and T id).

Retry link Sent in the failure email:
<participant retry_payment_url>/retry-payment?ref=<registration_id>%20<T id>&caps_transaction_id=<CAPS id>

The link never changes and revoke does not disable it. Each time it opens, rx asks BX for the row with this T id and picks the screen from its status:

CONFIRMED: Actions Already Completed. NOT_RECEIVED (revoked): the revoked message with the revoke date. PENDING or FAILED: the payment page.

  • An additional sale is one row in program_participant_transaction (is_additional_sale = true), created by the teacher.
  • Payments update that same row. A Pay click never creates a new one.
  • Online: the participant pays with the link in the email. Offline: the teacher records the payment in BX.
  • The participant always gets the request email. Only the teacher CC is optional.
  • No reminder and no expiry: an unpaid T stays PENDING and balance_due stays raised until it is paid or revoked.
  • Revoke is the same for online and offline, and works only while T is PENDING.
  • Offline Pending still emails a pay link. If the participant pays online with it, T switches to the online payment method, and the teacher can no longer edit or revoke it.
  • If the payment fails, T becomes FAILED. The teacher cannot edit it or create a new additional sale.
  • The participant has to pay again with the link in the failure email, and the same T is updated.
